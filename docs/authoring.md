# Как писать тему

Контракт для авторов контента. Образец уровня — `src/content/topics/pron-personal.ts`. Типы — `src/content/types.ts`, разметка предложений — шапка `src/content/sentence.ts`, граф — `src/content/graph.ts`, схемы и их ключи `focus` — `src/visuals/catalog.ts`. Паспорт темы (название, схема, границы `scope`, ожидаемый объём `size`) уже есть в `src/content/catalog.ts`: его не меняем, пишем только содержимое.

Проверка: `npm run validate` (из корня проекта). Тема готова, когда валидатор зелёный **и** каждое предложение перечитано глазами по чек-листу в конце.

## Файл

`src/content/topics/<id>.ts`:

```ts
import type { TopicBody } from '../types'

export default {
  summary: 'Одна строка: суть темы.',
  ref: [ /* справочник */ ],
  items: [ /* навыки */ ],
} satisfies TopicBody
```

## Язык и стиль

- Объяснения по-русски, коротко и простыми словами. Термин — только с русской расшифровкой: «подлежащее (кто делает)».
- Английский британский: colour, flat, holiday, at the weekend, autumn, queue, mobile phone. Орфография британская (realise, travelling, centre).
- Слова уровня A1–B1 (Oxford 3000), предложения 3–10 слов, взрослые бытовые ситуации: работа, дом, поездки, друзья, магазин, IT. Имена простые: Anna, Tom, Kate, Max, Ben, Lucy, Mr Smith. Без политики, религии, болезней, насилия.
- Свои предложения. Ничего не копировать из учебников и корпусов.
- Русский перевод `tr` естественный, как сказал бы человек, а не подстрочник.

## Справочник `ref` — 4–7 блоков

1. `visual` — главная схема темы (`id` из паспорта) с подходящим `focus` и подписью-фразой.
2. `rule` — 1–3 правила: `title` до 40 символов, `text` 1–3 предложения (≤ 420 символов), 2–3 примера `{ s, tr }`.
3. `contrast` — «Как в русском»: та же мысль по-русски (`ru`, размечено) и по-английски (`en`), `note` — чем отличается устройство.
4. `mistakes` — 3–6 типичных ошибок русскоязычных: `wrong` → `right` + `note` (≤ 90 символов).
5. По желанию: `tip` (одна проверка-лайфхак), `table` (короткая таблица форм; ячейки — разметка).

## Навыки `items`

Навык — одно атомарное правило, форма или слово. Его расписание повторений ведётся отдельно, поэтому:

- `id`: `<id темы>.<slug>` латиницей через дефис. После публикации не меняется.
- `skill`: до 80 символов, формулировка самого правила: «him — после глагола и предлога».
- `focus`: ключ из `VISUALS[<схема темы>].focus` — что подсветить на схеме при разборе ответа. Ставь всегда, когда есть подходящий ключ.
- `why`: до 180 символов. Объяснение, которое человек увидит после ответа. Можно задать у навыка (общее) или у варианта (частное).
- `variants`: 3 разных предложения на одно правило (минимум 2). Разная лексика и ситуации, иначе запоминается строка, а не правило.
- Количество навыков — около `size` из паспорта.

### Режимы

| mode | Что делает человек | Что обязательно в варианте |
|---|---|---|
| `gap` (по умолчанию) | заполняет пропуск: сначала выбором, потом с клавиатуры | `s` с одним `[ответом_X]`, `tr`, `options` — 2–3 неверных варианта; `accept` — другие верные ответы |
| `order` | собирает предложение из плиток | `s` без пропусков, `tr`; `accept` — другие верные порядки; `from` — исходные фразы для склейки; `options` — лишние плитки |
| `choice` | выбирает ответ, когда вводить нечего | `answer`, `options`, плюс `s` с `{целью}`, `visual` или `q` |
| `tag` | раскрашивает каждое слово | `s`, где у **каждого** слова есть `_X`, `tr` |
| `graph` | строит граф: сказуемое → подлежащее → к чему относится слово | как `tag` + `graph` |
| `pick` | находит слово в предложении | `s`, где верные слова в `{ }`, `q` («Найди прилагательное»); `model` — образец «та же роль» |

Пропуск должен однозначно определяться предложением **и** переводом `tr` (его видно на экране). Если подходят два ответа, перепиши предложение или добавь второй в `accept`. Неверные `options` — правдоподобные ошибки (типичные для русскоязычного), но в этом контексте точно неверные.

## Разметка частей речи

Размечай **все** знаменательные слова, и в `ref`, и в `items`: при разборе ответа предложение показывается раскрашенным целиком. Красим по функции, одинаково для английского и русского:

| Код | Что | Английский | Русский |
|---|---|---|---|
| N | существительное | book, Anna, Anna’s | книга, Анна |
| P | местоимение, включая my / his, it и there в There is | I, him, my, mine, myself, who, somebody, it, there | я, его, мой, себя, кто, никто |
| D | артикль, определитель | a, the, this (+ сущ.), some, every, no (+ сущ.) | — (в русском «этот», «какой-то» — P) |
| M | числительное | two, first | два, первый |
| J | прилагательное | big, tired, my **own** | большой, рад; причастие — J (читающий) |
| V | смысловой глагол, be как основной глагол | work, is (She is a doctor) | работать, был |
| A | вспомогательный, модальный | do / does / did, be в Continuous, have в Perfect, will, can, must, don’t, isn’t (если вспомогательный) | буду (в «буду читать») |
| R | наречие, частица фразового глагола | often, here, very, up (look up) | быстро, здесь, хорошо; деепричастие — R (читая) |
| I | предлог | in, on, at, with, about | в, на, у, с |
| C | союз | and, but, because, when, that (союз), if | и, но, потому что, что (союз), когда (союз) |
| X | частица | not, to перед глаголом | не, бы, ли, же |

Сокращения: `I_P +’m_V` / `I_P +’m_A` (по роли be), `it_P +’s_V`, `don’t_A`, `can’t_A`, `isn’t_V` (be основной) или `isn’t_A` (be вспомогательный). Многословный токен — через `~`: `in~front~of_I`, `a~lot~of_D`, `Mr~Smith_N`. Апостроф — типографский `’`.

## Граф (`mode: 'graph'`)

`graph: "1>2 subj, 3>4 attr, 4>2 obj"` — номер слова > номер хозяина и отношение. Слова считаются с 1, пунктуация не считается, `+’s` — отдельное слово. Корень (сказуемое) не пишется. Короткие предложения 3–7 слов, без придаточных.

| Отношение | Кто на ком висит |
|---|---|
| `subj` | подлежащее → сказуемое |
| `obj` | дополнение (и косвенное: give **Mum** the book) → глагол |
| `compl` | после be / seem / become: She is **a doctor**, He is **tired** → be. В русском без связки корень — само сказуемое: Она_P врач_N → «1>2 subj» |
| `attr` | артикль, определитель, прилагательное, числительное, my / his → существительное |
| `adv` | наречие → глагол (very → прилагательное); существительное после предлога в роли «где? когда? как?» → глагол |
| `aux` | вспомогательный / модальный → смысловой глагол |
| `part` | not, to, не, бы → глагол; there в There is → be |
| `prep` | предлог → своё существительное (in the room: in → room, the → room, room → глагол как `adv` или `obj`) |
| `cc`, `conj` | Tom **and** Kate: Kate → Tom `conj`, and → Kate `cc` |

Придаточные (только в теме cascade-reading): сказуемое придаточного висит на сказуемом главного как `adv` (when, because, if, although) или как `obj` (I know **that** he left — left → know `obj`); союз — `mark` к сказуемому придаточного. Относительное придаточное (the man **who** lives here): сказуемое придаточного (lives) висит на определяемом существительном (man) как `attr`, who — `subj` к lives, which/that — `subj` или `obj` к сказуемому придаточного по роли.

В паре RU/EN одна мысль даёт одинаковый граф для знаменательных слов: `Мама_N передвинула_V стол_N .` → `1>2 subj, 3>2 obj`; `Mum_N moved_V the_D table_N .` → `1>2 subj, 3>4 attr, 4>2 obj`.

## Русские предложения (`lang: 'ru'`)

`s` на русском, `tr` — английский перевод. Те же коды. Трудные пары, на которых строится тренажёр: хорошо (R) / хороший (J); рад, готов — краткое прилагательное (J); приставка внутри глагола ≠ предлог (вошёл в дом: «в» — I); что, как, когда — союз (C) в «Я знаю, что он дома», местоимение (P) / наречие (R) в «Что ты делаешь?», «Когда ты придёшь?»; причастие (J), деепричастие (R).

## Чек-лист перед сдачей

1. Каждое английское предложение грамматически верно и звучит естественно для британца.
2. Ответ в `gap` единственный при данном `tr`. Ни один из `options` не подходит.
3. `why` объясняет именно этот вариант и не противоречит `rule`.
4. Части речи размечены по таблице выше, у всех знаменательных слов.
5. Перевод `tr` верен и естественен.
6. Нет повторов предложений между навыками; у навыка 3 варианта с разной лексикой.
7. Не залез в чужую тему: смотри `scope` соседних тем в `catalog.ts`.
8. `npm run validate` зелёный.
